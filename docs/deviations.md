# 偏差清单

flowmesh 所有可从外部观察到的行为，都与 Tailscale 官方客户端保持一致。本清单列出的是有意为之的偏差，清单之外的差异一律按 bug 处理（设计稿 §4.4）。

| # | 偏差 | 原因 | 依据 | 状态 |
|---|---|---|---|---|
| 1 | prefer mode (all DERP nodes `STUNPort=-1`): never initiates direct connections, does not run STUN, does not send or accept CallMeMaybe; **still replies to UDP pings** and reports local endpoints, so LAN peers can still go P2P | WanFlow prefer relay mode, consistent with wanflow-mesh | disco.md §6, OBS-20261010-relay-modes | Implemented (M5) |
| 2 | An `http://` control URL on any port is used as given, in plain HTTP; no TLS is forced and nothing falls back to 443 (the control connection is encrypted by Noise either way) | WanFlow control URLs are `http://ip:<high port>` | official behavior: OBS-20261010-official-http-control; flowmesh: `lab/scripts/high_port_control.sh` (joins through port 18080, no packet to the control server's 443) | Implemented, verified (M8) |
| 3 | No telemetry, no auto-update, no control-initiated requests (c2n), no bootstrap DNS to built-in third-party hosts, no default control server (see #8) | zero-telemetry promise (design §7.4) | the official client queries vendor DERP hosts for bootstrap DNS: OBS-20261010-official-http-control, cli.md §6 | Implemented (none of these exist in the code); lab outbound audit: M8 Task 7 |
| 4 | 支持内核 WireGuard 后端 | 性能 | 设计稿 §3.4 | v2 |
| 5 | ACL rules that fail to parse are fail-closed: the previous valid rules stay; with no valid rules ever, all inbound is refused | security first | flowmesh: `engine/logic.rs` `apply_netmap` test, dataplane fail-closed test (filter.md F2). The official behavior cannot be observed in the lab: headscale validates policies and never sends unparsable rules | Implemented; official behavior unobservable |
| 6 | **strict mode** (self node carries `tag:relay-strict`): no direct traffic of any kind — no reply to UDP pings, CallMeMaybe ignored. **Stricter than wanflow-mesh before 92a3ed66a**: older wanflow-mesh accepted the peer's CallMeMaybe under strict and went direct; wanflow-mesh 92a3ed66a (2026-10-11, not yet rolled out) refuses it too, so the two agree once it ships. The peer relay stays allowed in strict on both | honor the product promise "always relay, no P2P" | disco.md §6, OBS-20261010-relay-modes | Implemented (M5) |
| 7 | `logout` gives up after 15 s when the control server cannot be reached and exits 1; the end state is the same as the official client's (Stopped, still logged in, preferences kept) | the official `logout` waits until the server answers or the caller kills it, which leaves scripts (the WanFlow gateway agent) hanging | cli.md §1, OBS-20261010-cli-diff | Implemented (M7) |
| 8 | No default control server: `up` without `--login-server` (first time, or after `logout`) is refused | zero-telemetry promise; the official client falls back to its vendor's control server, observed contacting it from the lab after a logout | cli.md §1, OBS-20261010-cli-diff | Implemented (M7) |
| 9 | After a peer relay server restarts (allocations lost), flowmesh retries its handshake for 5 s, then requests a new allocation at once: back on the relay 3–7 s after the server returns. The official client waits for its next 30 s allocation round (19–21 s) | faster recovery; the request rate stays bounded (one round per failed bind, at least 5 s apart, only while the relay is down and traffic continues) | `lab/scripts/peer_relay_diff.sh`, three runs; flowmesh-udprelay `bind_is_retried_then_the_allocation_is_given_up` | Implemented (M10) |
| 10 | Subnet router netfilter rules exist only while routes are advertised, in chains `fm-forward` / `fm-postrouting` (or an `inet flowmesh` nftables table when iptables is absent), and SNAT matches the mesh's source range (`100.64.0.0/10`, `fd7a:115c:a1e0::/48`) instead of a fwmark | the official client installs its `ts-*` chains whenever it runs and marks forwarded packets with 0x40000/0xff0000; the CPE agent reserves those mark bits (v3), and a host that routes nothing gets no rules | OBS-20261011-subnet-router-official; `lab/scripts/subnet_router_check.sh` | Implemented, verified |
| 11 | The peerapi exists only on an exit node and serves only the DNS proxy (`/dns-query`); no Taildrop or other peerapi endpoints | the official client runs a peerapi on every node; flowmesh needs it only so that peers using a flowmesh exit node can resolve names, which official clients require of any exit node | OBS-20261011-exit-node-official; `lab/scripts/exit_node_check.sh` | Implemented, verified |
| 12 | Exit node policy routing (rules 5210–5270, table 52) exists only while an exit node is set | the official client keeps its rules and table 52 whenever it runs; flowmesh routes through main-table routes otherwise and adds nothing a host does not need | OBS-20261011-exit-node-official; `lab/scripts/exit_node_check.sh` (rules gone after `--exit-node=`) | Implemented, verified |
| 13 | `netcheck` measures only the relay map flowmeshd received from the control server; when the daemon has none (not running), it refuses | the official CLI then fetches a default map from its vendor's control plane and probes vendor relays, observed from the lab (`netcheck-stopped.txt`) | OBS-20261012-cli-more-official; `lab/scripts/cli_more_check.sh` | Implemented, verified |
| 14 | The SSH server's host keys are Ed25519 and ECDSA P-256; there is no RSA host key | the Rust RSA implementation carries an open timing advisory (RUSTSEC-2023-0071); every OpenSSH since 5.7 takes ECDSA. Clients learn the keys from `Hostinfo.sshHostKeys`, so nothing else changes | OBS-20261012-ssh-official (official: RSA, ECDSA, Ed25519); docs/protocol/ssh.md §3 | Implemented, verified (`lab/scripts/ssh_check.sh`) |
| 15 | SSH rules whose action asks the control server to check (`holdAndDelegate`) or requires session recording (`recorders`) refuse the login with a message saying so | neither the check round trip nor recording exists in flowmesh; refusing is the safe reading. headscale sends neither (its `check` is an accept with a session duration, which flowmesh enforces) | docs/protocol/ssh.md §2; `flowmesh-ssh` policy tests | Implemented |
| 16 | `flowmesh serve` does not serve HTTPS: without a mode (official default HTTPS), `--https` and `--tls-terminated-tcp` are refused with the reason | HTTPS needs certificates the control server issues; headscale does not (the official client fails with `error enabling https feature: … 404`, or stores a TLS-terminated forwarder that cannot work) | OBS-20261012-serve-official (`https-default.txt`, `tls-terminated.txt`); docs/protocol/serve.md §5 | Implemented, verified |
| 17 | Serve services (`--service`, `advertise`, `drain`, `clear`, `get-config`, `set-config`, `--tun`) and `--accept-app-caps` are refused | they need control server support (service addresses, approval) headscale does not have; the official client stores a service that is never approved | OBS-20261012-serve-official (`service-flag.txt`); serve.md §5 | Implemented |
| 18 | Serve's reverse proxy does not send `Tailscale-Headers-Info` (a link to the vendor's documentation) nor force `Accept-Encoding: gzip` (an artifact of Go's HTTP client) to the backend | neither carries information a backend needs; the identity and forwarding headers are the official ones | `lab/scripts/serve_compare.py` | Implemented, verified |

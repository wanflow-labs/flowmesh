# SSH (`--ssh`, `flowmesh ssh`, `flowmesh nc`)

Sources: `OBS-20261012-ssh-official` (`lab/scripts/ssh_observe.sh`, official client v1.94.2 as server and client, headscale 0.26 policy with an `ssh` section). flowmesh is checked case by case against the same situations by `lab/scripts/ssh_check.sh` (official client → flowmesh server, `flowmesh ssh` → official server).

## 1. What the control server sends

- **Policy.** `MapResponse.SSHPolicy` (`{"rules": [...]}`), present when it changed; absent means unchanged (tailcfg semantics, kept by flowmesh). Each rule: `principals` (`nodeIP`, `node` (stable ID), `userLogin`, `any`), `sshUsers` (requested user → local user), `action` (`accept`, `reject`, `message`, `sessionDuration` (ns), `allowAgentForwarding`, `allowLocalPortForwarding`, `allowRemotePortForwarding`, `holdAndDelegate`, `recorders`), optional `ruleExpires`.
- **headscale 0.26** sends one rule per policy `ssh` entry whose destinations include this node: one `nodeIP` principal per source address, `sshUsers` mapping each listed user to `"="`, and for both `accept` and `check` an accept action with `allowAgentForwarding` and `allowLocalPortForwarding` (`check` adds `sessionDuration`). `autogroup:nonroot` arrives as a literal user name.
- **Host keys.** A node running the server advertises its keys in `Hostinfo.sshHostKeys` (lower-case key) in authorized_keys form; peers see them in the netmap, and `status --json` shows them per peer as `sshHostKeys`. The official server has RSA, ECDSA P-256 and Ed25519 keys (state directory `ssh/`; without `--statedir` it runs no SSH server: "no var root for ssh keys").

## 2. Who may log in as whom

Rules are tried in order. A rule applies when one of its principals names the connecting peer and its `sshUsers` gives a local user for the requested name (exact key, else `*`; value `=` keeps the name, a name renames, `""` refuses). The first rule that applies decides: accept as that local user, or reject. No rule: refused with `tailnet policy does not permit you to SSH as user "<name>"`.

Observed (`ssh-*.txt`): `root` and `alice` accepted; `carol` (exists locally, covered only by `autogroup:nonroot`), `daemon` (exists, not listed) and an unknown name refused with that message — **`autogroup:nonroot` is not expanded** by the official server, and flowmesh does the same.

flowmesh additionally refuses (deviation #15): actions with `holdAndDelegate` (the official "check" round trip to the control server) or `recorders` (session recording), with a message saying so. Expired rules (`ruleExpires` in the past, or unreadable) are skipped. An accepted local user that does not exist is refused.

## 3. The server

- **Port 22 of the node's mesh addresses**, only for connections that arrive over the mesh. The official client intercepts them in its userspace network stack; flowmesh's TUN delivers them to the kernel, so the dataplane rewrites TCP port 22 of this node's addresses to the server's own port (a random port on the mesh addresses) and the replies back to 22 (checksums updated incrementally, RFC 1624). The packet filter sees port 22, as the official one does. Without `--ssh`, port 22 reaches the host (official: `connection refused` when nothing listens there).
- **Only connections from the mesh.** The listener's port is reachable by local processes too (`SO_BINDTODEVICE` on the mesh interface does not stop the kernel from delivering local connections to a mesh address, seen in the lab). Two independent checks keep them out: (1) admission — the dataplane records the source of every SYN it delivered from port 22 after WireGuard decryption and the AllowedIPs check, and the server accepts a connection only with such a record (one use, 30 s); (2) the source address must belong to a peer in the netmap (never this node). `ssh_check.sh` connects as an unprivileged local user to the server's port, to port 22 of the node's own address, and over IPv6 with a peer's address as the source (`IPV6_FREEBIND`): all refused, and the server logs the refusal. (The spoofed-source connection cannot complete its handshake anyway: the reply is routed to the real peer.)
- **Authentication** is the `none` method: identity comes from the network. The server identifies itself as `SSH-2.0-flowmesh` (official: `SSH-2.0-Tailscale`). Host keys: Ed25519 and ECDSA P-256, created on first start under `<state dir>/ssh/` (0600, directory 0700) and kept (deviation #14: no RSA key).
- **Refusals.** The official server sends the reason as an authentication banner, then closes: OpenSSH prints `tailscale: tailnet policy does not permit you to SSH as user "carol"` and `Connection closed by …`, exit 255. flowmesh's SSH library sends banners only before it knows the user, so the reason travels as the instructions of a keyboard-interactive round with no prompts, and the connection is closed on the (empty) answer. OpenSSH prints the same two lines (`flowmesh:` instead of `tailscale:`), exit 255 (`ssh-carol-nonroot.txt` in both runs).
- **Sessions** run as the local user through a helper: flowmeshd starts itself as `flowmeshd be-child ssh --uid … --gid … --groups … --home … [--tty …] -- <program>` (the official server does the same with `tailscaled be-child ssh`). The helper starts a new session, takes the pty as its controlling terminal, sets the user's supplementary groups, group and user (and checks that root cannot be regained), enters the home directory (else `/`), and execs. The daemon itself never changes identity and has no unsafe code.
  - `exec`: `<login shell> -c <command>`; `shell`: the login shell as a login shell (`-sh`); `subsystem sftp`: the host's `sftp-server` if there is one, else flowmesh's built-in SFTP server, run in the helper after the switch (OpenWrt has no `sftp-server`; the official server has a built-in one too).
  - Environment, as observed (`ssh-alice-env.txt`): `HOME`, `PATH`, `SHELL`, `USER`, `SSH_CLIENT`, `SSH_CONNECTION` (server port 22); with a pty also `TERM` and `SSH_TTY`; `SSH_AUTH_SOCK` with agent forwarding. `PATH` comes from `/etc/login.defs` (`ENV_SUPATH`/`ENV_PATH`) when set, else `/usr/local/bin:/usr/bin:/bin` (root: with the `sbin` directories). Client `env` requests are refused.
  - Exit status and exit signal are passed back (`exit 3` → 3; a shell killed by SIGTERM → ssh exit 255); stdin EOF closes the program's stdin; window changes resize the pty; `signal` requests are delivered; closing a pty session hangs up its process group.
- **Forwarding.** Local (`-L`, `direct-tcpip`) when the rule allows it, connecting from the daemon like the official server; agent forwarding when allowed, through a socket in a fresh 0700 directory owned by the user; remote forwarding (`-R`) refused (headscale never allows it).
- **Session duration.** A rule's `sessionDuration` ends the connection when it is up.
- **Logs.** One line per accepted or refused login (`ssh: login of <node> (<ip>) as "<user>" accepted|refused: <reason>`), an audit line (`ssh: audit: login user=… uid=… from=… node=…`), one per started program.
- **Turning it on and off** (`set --ssh`, `set --ssh=false`) needs no engine restart: listeners, host keys in Hostinfo and the port 22 redirect follow the setting.

## 4. The client

- `flowmesh ssh [user@]<host> [args...]` runs the system `ssh` like the official wrapper (`ssh-debug-exec.txt`): `-o UserKnownHostsFile "<config>/flowmesh/ssh_known_hosts" -o UpdateHostKeys no -o StrictHostKeyChecking yes -o CanonicalizeHostname no -o ProxyCommand "<flowmesh>" nc %h %p [user@]<peer address> [args...]`. The host is a peer's name or address (IPv4 preferred). The known_hosts file is rewritten from the netmap each time, each key under the peer's DNS name (with the trailing dot) and each of its addresses, in the official layout (`ssh-known-hosts.txt`).
- `flowmesh nc <host> <port>` connects stdin/stdout to a peer's TCP port (the official one dials through tailscaled; flowmesh connects through the kernel route over the TUN).
